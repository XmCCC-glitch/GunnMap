# User visit counter

Count normal page openings, including agents reading the site for a user.
**Visits caused by agent development, QA, debugging or deployment checks do not
belong in the user total.** No CAPTCHA, bot classifier, Turnstile widget, or
Turnstile permission is needed. A Worker/D1 backend stores the shared total.

Each new browser document (including refreshes and new tabs) counts once. SPA
navigation and retries reuse the opening ID. The counter starts at zero when the
database migration initializes it; previous traffic cannot be recovered.
The footer appears only in Pages builds with `VITE_VISITS_API_URL` configured.

## Development exclusion and undo

- Before development/QA browsing, open `/GunnMap/?stats=off` in that browser
  profile. This saves a persistent opt-out; localhost never records visits.
- If an opening was accidentally counted, open `/GunnMap/?stats=undo` in the
  **same profile**. This opts out and reverses its latest opening. Repeating the
  URL is safe: it targets the same receipt and cannot subtract twice.
- To undo a specific earlier development opening, use
  `/GunnMap/?stats=undo&visit=<its-visitId>`. The matching receipt must exist in
  that profile. The browser retains its last 100 receipts for up to 30 days of
  backend rollback. Undo only receipts generated by your development work.
- `/GunnMap/?stats=on` explicitly re-enables normal counting in that profile.
- Reading `GET <API>/visits` never increments the counter. An agent fetching
  content without JavaScript can record a user-requested read with the API below;
  development agents must use read-only requests instead.

## API

All mutations require `Origin: https://xmccc-glitch.github.io` and JSON. Browsers
send no credentials, schedules, room selections, names, or emails.

`POST /visits` accepts `{ "visitId": "<UUID-v4>", "undoToken": "<UUID-v4>" }`.
Generate two random UUIDs per opening and retain both until the request succeeds.
Repeating a visit ID never adds another count. User-agent strings and webdriver
status do not affect counting. A request with `purpose: "development"` is
read-only, as an additional explicit safeguard.

`DELETE /visits/<visitId>` accepts `{ "undoToken": "<that-opening-token>" }`.
It reverses only that receipt and returns `{ total, startedAt, removed }`.
An incorrect token cannot remove another visit. It leaves a random-ID tombstone
so a late or retried POST cannot restore the excluded visit. There is no public
reset, arbitrary decrement, record listing, or bulk-delete endpoint.

The database stores a total, start timestamp, random opening IDs, hashed undo
capabilities, timestamps and exclusion flags. Individual records expire after
30 days, leaving the all-time total intact; undo is available during that period.
Application logs are disabled. Rate limiting uses the edge-provided IP without
storing it in the database. Local receipts are capabilities, not account tokens;
keep them scoped to the development run that created them.

This measures cooperative browser/API traffic. Pure HTTP reads without an
explicit visit event, offline visits, blocked storage, and failed requests are
not counted. Public analytics cannot independently prove a request's purpose;
development agents must follow AGENTS.md.

## Deployment

1. Provision `gunnmap-visits` in the intended Cloudflare account; set its
   `database_id` in `wrangler.jsonc` and apply the migration once.
2. Deploy this Worker using the existing Workers/D1 account authorization. There
   are no runtime secrets or CAPTCHA permissions to configure.
3. Set the repository Actions variable `VITE_VISITS_API_URL` to its `/visits` URL.
4. Merge the reviewed Pages change into `github-page-10/6` and let Pages deploy.
   Later deployments must not reset the database.

Test with local databases. Any temporary production smoke-test opening must be
undone with its own receipt, then confirm the total returns to its initial value.
